# 사전문의 국가명·국적 변경

## 2026-09-11 적용 상태

- Supabase 국가명 기준표·국적 열·저장 검증 적용 완료. 기존 ISO2 국가 코드 잔여 0건.
- 국내·해외 × 단일·이중국적, 익명 접수, 누락·중복 차단 검증 통과. 테스트 행은 모두 롤백.
- `send-admin-email` 버전 11 ACTIVE, JWT 검증 유지, 배포 소스 일치 확인.
- 공개 양식·국가명 스크립트·저장 코드·개인정보 처리방침 배포 완료.
  소스 커밋 `1d80811d1b1e70b46557fd701a675de78eb7103f`,
  정적 페이지 커밋 `871242666ae4974e179dfdbfe73d9a6338f1d8fd`,
  GitHub Pages 실행 `34566380724` 성공.
- 관리자 화면에 현재 국적·이중국적 표시와 국적 검색을 추가했다.
  데이터베이스 마이그레이션·알림 함수·검증 자료를 함께 저장소에 반영한다.
  운영 Supabase에는 해당 변경이 이미 적용됐다.

국가 선택값과 저장값을 법무부 하이코리아의 한글 명칭으로 통일한다.
영문 화면에는 전체 영문명을 표시하며 저장값은 한글 화면과 동일하다.
`US` → `미국`, `RU` → `러시아(연방)`, `TH` → `타이`, `AE` → `아랍에미리트연합`.

국내·해외 체류 여부와 관계없이 현재 국적과 이중국적 여부를 받는다.
이중국적을 선택하면 서로 다른 두 번째 국적이 필수다.
기존 접수 건의 국적과 이중국적 여부는 추정하지 않고 NULL(미수집)로 유지한다.

## 국가명 출처

- 한글 명칭·법무부 코드: https://www.hikorea.go.kr/info/CheckExprYmdByPassNoR.pt
- 현행 선택 목록·영문 명칭: https://www.visa.go.kr/
- 확인일: 2026-09-11
- 원문 선택값: `scripts/moj-countries-source.json`
- 실행 목록: `js/moj-countries.js`의 `countries`

비자포털의 212개 항목에 하이코리아의 한국·북한·무국적·국적불명을 추가했다.
하이코리아에 남아 있는 역사적 국가, 민족 구분 및 국제기구 코드는 선택란에서 제외했다.
국적 전용 항목은 거주 국가 선택에 표시하지 않으며 한국은 해외 거주 국가에서 제외한다.
영문 국가명의 축약 표기는 읽을 수 있는 명칭으로 풀고, `officialEn`에 원문을 유지했다.

## 운영 적용 순서

대상 Supabase 프로젝트: `gqistzsergddnpcvuzba`.
아래 순서로 적용해야 새 양식이 아직 없는 데이터베이스 열에 쓰기를 시도하지 않는다.

1. `migrations/20260911_pre_consultation_nationalities.sql`을 적용한다.
   국가명 기준표와 국적 3개 열을 추가하고, 인식 가능한 기존 국가 코드만 전체 명칭으로 변환한다.
   기존 개인정보 접근 정책은 유지하며 국적 조합과 거주 국가를 데이터베이스에서도 검사한다.
2. 실제 배포된 `send-admin-email` 소스를 먼저 읽어 저장소와 비교한 뒤,
   사전상담 조회 열과 본문의 국적·이중국적 행 변경을 적용해 재배포한다.
   다른 알림 경로 및 운영 전용 변경은 보존한다.
3. 웹사이트 변경을 `main`에 반영한다. 정적 페이지 생성 및 GitHub Pages 배포 성공을 확인한다.

연결 전에는 1·2단계의 실제 적용 여부를 확인할 수 없으므로 새 양식을 운영에 게시하지 않는다.

## 검증

```
node scripts/build-site.js
npm run validate
node --test scripts/test-preconsultation.js
```

국가명 216개와 원문 일치, 기존 ISO2 코드 매핑, 양 언어의 선택값,
국내·해외 × 단일·이중국적 저장, 중복·누락 국적 거절을 확인한다.
오프라인 검증은 실제 문의나 알림 메일을 생성하지 않는다.

실제 데이터베이스 적용 후에는 열·트리거·제약조건을 확인하고,
트랜잭션 안에서 가상 접수의 저장값을 검증한 뒤 ROLLBACK한다.
메일 함수 배포 확인을 위해 테스트 메일을 임의로 발송하지 않는다.

롤백이 필요하면 웹사이트와 알림 함수부터 이전 버전으로 복구한다.
새 데이터베이스 열은 삭제하지 않는다. 이전 양식의 접수는 국적 미수집으로 계속 허용된다.
